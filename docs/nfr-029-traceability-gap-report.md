## Two items that needed an explicit ruling (status update 2026-09-19)

These two were originally flagged because no amount of implementation work alone could resolve
them -- they were disagreements about the *identifier registry itself*, which CP-011's own
consequence clause says a person must never resolve by silent edit ("rule identifiers are never
renumbered or reused"). One is resolved; one is partially closed by later implementation and still
open as a registry question.

### 1. Spec-named `PD-*` rule ids missing from the wire-grammar contracts -- partially closed

`spec.md` names 18 distinct validator-rule ids in its own prose. As of this report's original
generation, only 2 (`PD-EXT-002`, `PD-MODE-001`) also appeared in `contracts/*.abnf`. As of
2026-09-19, 6 do: `PD-NFC-002`, `PD-MODE-001`, `PD-EXT-002`, `PD-A11Y-003`, `PD-TBL-001`, and
`PD-2D-001` (across `document.abnf` and `container.abnf`), added as their owning M09-M15
milestones landed. The remaining 12 -- `PD-SCALAR-001`, `PD-DUP-001`, `PD-EXT-001`, `PD-EXT-003`,
`PD-LANG-001`, `PD-BIDI-001`, `PD-A11Y-001`, `PD-A11Y-002`, `PD-A11Y-004`, `PD-PREV-001`,
`PD-FONT-001`, `PD-INFER-001` -- still exist only as a name in spec.md prose, with no corresponding
ABNF rule anywhere. Each of these 12 has a real conformance case in this module's Go source (per
the Summary above, the mechanical gap count is 0), so implementation-side coverage is not blocked;
what remains open is a registry-hygiene question -- whether each of these 12 rule ids should get a
formal ABNF definition to match its already-implemented behaviour, or whether some are intentionally
prose-only. Not yet ruled on.

### 2. `PD-NORM-001` was renamed to `PD-NFC-001`/`PD-NFC-002` -- resolved

This report originally stated that spec.md's CON-002 verify clause claimed an unrecorded ruling by
Eyvar approving this rename, and that no such ruling existed anywhere in the repository. That claim
is now out of date: **`CQ-014` in `clarify.md` (dated 2026-09-15) records exactly this ruling**
("`PD-NFC-001`/`PD-NFC-002` is canonical... `spec.md`'s CON-002 verify clause corrected to cite
`PD-NFC-002`... with a note explaining the rename"), and `spec.md`'s CON-002 verify clause's own
text already reflects it. No further action needed on this item.
